# 客流系统使用手册

版本 0.3.0｜目录 passenger-flow-system-codex｜2026-09-16

## 一、系统能做什么

这是客流数据管理和跨云数据库迁移的实验系统。网页提供门店、设备、客流明细、汇总看板、数据库健康和迁移实验室。CLI 提供造数、持续增删改、迁移标记、停写、快照、比较与预检查。

八张业务表：

| 表 | 内容 |
|---|---|
| stores | 门店资料 |
| devices | 设备与门店关系 |
| flow_events | 客流事件与人数 |
| flow_hourly | 每店每小时进出人数汇总 |
| device_status_logs | 设备状态记录 |
| migration_markers | 迁移阶段标记和顺序号 |
| migration_batches | 批次状态、请求和实际影响行数 |
| migration_operation_audit | 每次事件修改的前后值审计 |

**数据口径**：people_count 表示人次；进店总量按人数求和，不按记录条数计算。今日净进店人数＝今日进店人次－出店人次，不代表去重人数或实际在店人数。flow_hourly 的 peak_count 当前保存小时内进出总人次，不是真实瞬时客流峰值。没有真实设备协议接入，演示数据和负载均为模拟数据。设备状态日志在造数时生成，批量事件 UPDATE 不同时修改设备状态日志。

## 二、部署方式怎么选

| 场景 | 应用在哪里 | 数据库在哪里 | 入口 |
|---|---|---|---|
| 最快本地试用 | Windows 11 | 项目内便携 MySQL 8.0.46 | start-local.bat |
| 验证你的 MariaDB | Windows 11 | MariaDB 10.3.39 服务器 | verify-configured.bat / start-configured.bat |
| VMware 实验 | Rocky Linux 8 虚拟机 | 同机或独立 MariaDB 10.3.39 | systemd 或 npm start |
| AWS 同构迁移练习 | EC2 Rocky Linux 8/9 | RDS MySQL 8.0 | Linux 安装脚本 |
| MariaDB 异构迁移练习 | Rocky 8/EC2 等 | 自建 MariaDB 10.3.39 | 同一应用，DTS 选 MariaDB 源 |
| 腾讯云目标 | CVM 或同等应用主机 | TencentDB MySQL | 迁移完成后切换连接 |

Node.js 最低要求 22.2.0，优先选 24；本次实际使用 Windows 24.19.0、Rocky 24.21.0。Rocky 8 的基础系统库满足 Node Linux x64 的构建基线，但仍应在目标主机执行版本和启动验证。[Node 官方构建说明](https://github.com/nodejs/node/blob/main/BUILDING.md)

MariaDB 10.3.39 的兼容目标是现有环境；10.3 系列已经结束维护，新建长期生产环境应另行规划受支持版本。[MariaDB 版本说明](https://mariadb.com/docs/release-notes/changelogs/changelogs-mariadb-10-3-series)

## 三、Windows 11 一键试用

### 3.1 准备

安装 Node.js 22/24，确保命令窗口可以运行 node 和 npm。使用完整项目路径，不要把文件拆散。初次启动需访问 npm 及 MySQL 官方下载站；后续已有依赖和运行文件即可离线启动。

双击 start-local.bat，等待出现「服务启动」，再用浏览器打开：

http://127.0.0.1:3030

脚本会安装缺失依赖、下载校验便携数据库文件、启动项目内 MySQL、创建本地业务表、补齐演示门店和设备。不会注册 Windows 服务，不需要 Docker。数据保存在 .local-mysql/data，应用配置在 .env.local。原有 .env 不会被替换。

首次只有门店/设备而没有客流时，在项目 PowerShell 窗口执行：

```powershell
$env:ENV_FILE = '.env.local'
npm run db:generate -- --rows 2000 --days 7
```

刷新首页查看数据。重复造数会继续新增，不会自动清空。

如果使用的是首次建表后的远程数据库，先执行一次 `npm run db:seed` 创建 5 个示例门店和 10 台设备；随后可在迁移实验室点击 Generate，或执行上述生成命令。

### 3.2 自动验证

双击 verify-local.bat。无交互调用：

```powershell
.\verify-local.bat --no-pause
```

验证脚本自动准备本地数据库，随后执行 ESLint、单元测试和数据库集成测试。集成测试为每次运行创建两个独立 pf_test_* 数据库，验证真实增删改、事务回滚、并发标记、负载、网页、认证、停写、全表摘要和结构差异。报告写入 reports/integration-时间戳.json。成功退出码 0；失败非 0。

测试库保留供核验，会占用磁盘；确认不需要后，由你在数据库管理工具中逐个核对名称再删除。脚本不自动删除数据库。

### 3.3 停止和再次启动

应用窗口 Ctrl+C，等待停止；再双击 stop-local-db.bat。停止不删除配置或数据。再次双击 start-local.bat 使用同一数据目录。

移动或改名目录前必须先停应用和数据库。不要同时启动两份使用同一 3030/33317 端口的项目。停止脚本核对数据库实际数据目录后才发停机命令。

### 3.4 Windows 连接 MariaDB 10.3.39

保留现有 .env；新机器从 .env.example 复制一份。填写：

```dotenv
NODE_ENV=production
APP_ENV_NAME=LOCAL
BIND_HOST=127.0.0.1
PORT=3030
DB_HOST=你的数据库地址
DB_PORT=3306
DB_NAME=passenger_flow_codex
DB_USER=应用账号
DB_PASSWORD=实际密码
DB_TIME_ZONE=+08:00
DB_SSL=false
MAINTENANCE_MODE=false
DB_READ_ONLY=false
APP_AUTH_USER=自定登录名
APP_AUTH_PASSWORD=自定强密码
```

不要把示例占位值直接当成实际配置。如果数据库提供 TLS，设置 DB_SSL=true 并填写服务器 CA 路径，保持证书验证。

先双击 verify-configured.bat：只读检查现有数据库和 12 个页面/接口；不会建库或造数。通过后双击 start-configured.bat。两种启动入口默认使用 3030，因此先关闭另一种应用。

普通应用账号需对业务库有 SELECT/INSERT/UPDATE/DELETE 权限；初始化账号额外需要 CREATE/ALTER/INDEX 等建表权限，集成测试账号还需创建独立测试库。DTS 使用独立迁移账号，不要把应用登录密码或数据库 root 密码作为共享凭据。

对一个**已确认可写的新实验库**初始化：

```powershell
$env:ENV_FILE = '.env'
npm run db:init
npm run db:seed
npm run db:ready
```

db:init 连接已存在的 DB_NAME 并创建/检查八张表；不会创建数据库、用户，也不会自动升级已存在但结构不同的旧表。若旧表结构缺字段或索引，应先备份并审阅差异再做数据库变更。

## 四、Rocky Linux 8 与 VMware

### 4.1 虚拟机准备

推荐 Rocky Linux 8.10 x86_64，至少 2 vCPU、4 GB RAM、20 GB 可用磁盘用于小规模实验。VMware 可选桥接或 NAT，确保 Windows 能访问虚拟机 SSH、应用能访问数据库地址。使用固定地址或 DHCP 保留地址。

先在虚拟机核验：

```bash
cat /etc/rocky-release
uname -m
node --version
npm --version
command -v node
mysql --version
```

已有 MariaDB 10.3.39 时无需重装。安装脚本不自动替换数据库或升级现有 Node，避免影响其他应用。

若没有 Node，优先使用所在环境批准的软件源安装 Node 24（或 22）；先查看 dnf module list nodejs 中实际提供的流，再选择。不要假定 Rocky 8 的所有镜像都提供相同 Node 版本。也可下载 Node 官方 Linux x64 发行包，核对 SHASUMS256 后由管理员安装到系统路径。systemd 示例要求 /usr/bin/node；若你使用其他安装位置，修改服务中的 ExecStartPre 与 ExecStart 为实际绝对路径，并保证 passenger 用户可执行。

### 4.2 部署代码

按 GitHub 文档 clone 项目，再执行：

```bash
cd ~/passenger-flow-system-codex
sudo bash deploy/install.sh
```

脚本支持 Rocky 8/9，检查 Node，安装 Nginx/rsync，建立 passenger 运行账号，将代码准备到 /opt/passenger-flow-codex，安装生产依赖、systemd 文件和 Nginx 样例。更新已有部署时先保存代码归档，保留服务器 .env、维护标志和报告；不执行 rsync --delete，不自动初始化数据库、不启动服务、不开放防火墙。

确认执行此脚本即表示你同意该服务器上的这些安装与配置变化。源码目录与部署目录不要混用。

编辑 /opt/passenger-flow-codex/.env，填写数据库和登录信息：

```bash
sudoedit /opt/passenger-flow-codex/.env
sudo chown passenger:passenger /opt/passenger-flow-codex/.env
sudo chmod 600 /opt/passenger-flow-codex/.env
sudo -u passenger env ENV_FILE=/opt/passenger-flow-codex/.env node /opt/passenger-flow-codex/scripts/verify-configured.js
```

若是源端新建实验库，先单独执行 db-init.js 和 seed.js；DTS 目标端等待迁移建表，不执行这两个脚本。

```bash
sudo systemctl start passenger-flow
sudo systemctl status passenger-flow --no-pager
curl -fsS http://127.0.0.1:3030/health
sudo journalctl -u passenger-flow -n 100 --no-pager
```

需要开机启动时再执行 sudo systemctl enable passenger-flow。

### 4.3 从 Windows 访问虚拟机

最简单的实验入口是 SSH 隧道，不额外开放应用端口。在 Windows PowerShell：

```powershell
ssh -N -L 3001:127.0.0.1:3030 你的SSH用户@虚拟机IP
```

保持窗口打开，浏览器访问 http://127.0.0.1:3001。配置 Basic 登录后浏览器会要求用户名和密码。

需要 Nginx 时，先检查现有站点是否占用 8080，审阅 /etc/nginx/conf.d/passenger-flow.conf.example，再启用：

```bash
sudo cp /etc/nginx/conf.d/passenger-flow.conf.example /etc/nginx/conf.d/passenger-flow.conf
sudo nginx -t
sudo systemctl enable --now nginx
```

SELinux 如阻止 Nginx 连接上游，应根据审计日志由管理员决定启用 httpd_can_network_connect，而非关闭 SELinux。公网必须经过 HTTPS；防火墙只允许必要的来源访问，数据库不要直接全网开放。当前 Nginx 样例监听 8080，供受控网段或 HTTPS 网关使用。

## 五、常用页面与操作

| 页面 | 操作与限制 |
|---|---|
| 首页 | 今日统计、七日趋势、门店对比等六张图表 |
| 门店 | 新增、编辑、查看；有关联设备/客流的门店拒绝删除 |
| 设备 | 新增、编辑、查看；有关联客流/日志的设备拒绝删除 |
| 客流明细 | 按门店、方向、日期过滤并分页 |
| 迁移实验室 | 批量 INSERT/UPDATE/DELETE、生成大小、负载、Marker |
| 迁移校验 | 展示数据及迁移检查信息；严格最终比较使用 CLI |
| 系统健康 | 数据库连接、表状态和运行环境 |

批量操作每次最多 200000 条，分块事务执行。单块内客流、审计、小时汇总和已影响行数一起提交；整批不是一个无限大事务。中断时已提交块保留，不能将 FAILED 批次理解为全部回滚。审核 migration_batches.affected_rows 和审计记录，确认后再继续。

输入大小 MB 的功能是按估算字节数计算有限行数，不保证 InnoDB 物理大小达到 ±5%；删除后物理文件也不一定立即缩小。不要把该功能当磁盘回收工具。

持续负载：

```powershell
$env:ENV_FILE = '.env.local'
npm run load:continuous -- --qps 20 --duration 60 --insert-percent 70 --update-percent 20 --delete-percent 10
```

qps 表示每秒业务操作数，一次操作包含多条 SQL，不等于数据库 SQL QPS。范围 1–500，三个比例须合计 100，允许某项为 0。按 Ctrl+C 或到时停止，等待在途任务结束，再观察 failedSql、实际速率与影响行数。不要同时从网页和多个终端启动无协调的负载。

## 六、AWS 部署

### 6.1 推荐的实验架构

EC2 部署应用，RDS MySQL 8.0 部署数据库；EC2 与 RDS 在可互通的 VPC 内。EC2 使用 Rocky 8/9 x86_64，部署流程同上一章。Amazon Linux 不适用当前 Rocky 安装脚本，不能直接声称已验证。

应用 .env 设置 APP_ENV_NAME=AWS、RDS endpoint、业务库、专用账号、TLS CA 和 Basic 登录信息。RDS 入站仅允许应用安全组及必要迁移来源。应用通过 ALB/HTTPS 或 SSH 隧道访问。

### 6.2 初始化与检查

仅源端新实验库执行 db:init、db:seed、造数。RDS 参数组检查 ROW 格式和 FULL 行镜像，开启满足持续迁移的 binlog，设置足够保留时间并根据参数是否动态决定重启。不要把数据库参数文件中的自建 MySQL 设置直接应用到 RDS。

RDS 管理账号可按官方过程设置并读取保留时间：

```sql
CALL mysql.rds_set_configuration('binlog retention hours', 24);
CALL mysql.rds_show_configuration;
```

24 小时只是本项目预检查下限，实际应覆盖全量迁移时间、网络故障恢复和运维窗口。[AWS 官方配置说明](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/mysql-stored-proc-configuring.html)

执行 npm run dts:precheck，修复明确失败项。该脚本为只读检查，无法代表跨云网络和目标权限已经通过；退出码 2 表示仍有待验证事项。

AWS 上自建 MariaDB 10.3.39 时，应选腾讯 DTS 的自建 MariaDB 源路径；不要把它伪装成 AWS RDS MySQL。AWS 上实际创建资源、费用和正式数据库变更需要你在账号内执行，本次代码交付不代表已部署到云。

## 七、腾讯云 DTS 迁移

### 7.1 先选择正确路线

腾讯云当前支持矩阵列出自建 MariaDB 10.0–10.6 到 TencentDB MySQL，以及 AWS RDS MySQL 到 TencentDB MySQL 的迁移路径；具体地域、版本组合和限制仍以创建任务时的控制台校验为准。[支持矩阵](https://cloud.tencent.com/document/product/571/58686)

MariaDB 10.3.39 → MySQL 是异构迁移，需检查 JSON/longtext、默认值和排序规则差异。[MariaDB/Percona 迁移至 MySQL](https://intl.cloud.tencent.com/zh/document/product/571/42644)

本地对两库做数据复制仅验证本系统比较器，不能代替 DTS 的全量、增量和网络验收。

### 7.2 迁移前准备

1. 备份源库，记录源/目标数据库版本和应用 Git 提交。
2. 目标业务库为空，由 DTS 执行结构与数据迁移。目标应用安装代码但不要执行 seed、generate 或负载。
3. 源/目标均使用 InnoDB；所有业务表具备主键。业务时区保持 +08:00，表名保持小写，核对字符集/排序规则和 lower_case_table_names。
4. 配置源 binlog：ROW、FULL、唯一非零 server_id（本项目要求大于 1），保留时间足够。MariaDB 使用自己的 GTID 实现，不需要为了本脚本强行设置 MySQL gtid_mode。
5. 建立独立 DTS 迁移账号，按官方所选路线授予 SELECT、复制读取及必要的系统库权限。控制台一致性校验可能需要向源端 __tencentdb__ 写入校验信息；这与应用业务库停写是不同范围，提前授权审阅。
6. 配置 DTS 到两端的网络路径、TLS和账号白名单。Windows/VMware 的 NAT 地址通常不能被云端直接访问，应使用受控 VPN、专线或符合控制台要求的接入方式。
7. 在源端运行 npm run dts:precheck，并完成 DTS 控制台预校验。不要仅凭某一个 PASS 就开始割接。

### 7.3 全量与增量演练

在源端可写时创建标记：

```bash
npm run migration:marker -- --type PRE_DTS --message "迁移前基线"
```

控制台选择结构迁移、全量+增量，选择八张业务表及所需完整对象，启动任务。全量阶段观察源库负载；进入增量后，源端进行小规模 INSERT/UPDATE/DELETE 及持续负载，观察目标对应记录、Marker 和 DTS 延迟。目标应用保持 MAINTENANCE_MODE=true 或 DB_READ_ONLY=true。

### 7.4 严格割接顺序

1. 停止**所有机器和终端**上的造数、网页负载、定时任务和其他写入者；等待在途操作归零、批次结束。
2. 源端仍允许最后一次写入时创建 PRE_CUTOVER Marker，记录 UUID 和 sequence。
3. 所有源应用实例执行维护停写；停止或隔离应用服务和外部写入者。不要只改一个终端的环境变量就认为全库已停写。
4. DTS 增量延迟归零，并确认目标存在最后 Marker；进行控制台数据一致性校验。
5. 两端在停写状态生成快照，比较内容和结构。需要多次重试时使用新文件名，避免覆盖历史证据。
6. 本地比较和 DTS 校验通过，记录最终位点/标记，按控制台流程结束迁移任务并确认状态。
7. 应用连接切到目标，先保持只读验证所有页面，再开放目标写入，执行一小笔业务操作和 POST_CUTOVER 标记。
8. 观察错误率、数据、时区和新数据增长。源端继续保留停写和备份。

维护操作（在每台应用机器、项目目录执行）：

```bash
npm run maintenance -- on
npm run maintenance -- status
```

.maintenance 是本目录本机标志，所有读取它的应用/CLI 会阻止新写入，但它不能取消已经提交的事务，也不能阻止其他账号直接改数据库。目标应用开放写入前，须同时检查 .maintenance、MAINTENANCE_MODE 和 DB_READ_ONLY；只移除文件而环境变量仍为 true 时仍然只读。

快照示例（源/目标各执行一次，ENV_FILE 指向各自配置）：

```powershell
$env:ENV_FILE = '.env'
$env:MAINTENANCE_MODE = 'true'
npm run db:snapshot -- --output source-final-001.json
```

Linux 对应：

```bash
ENV_FILE=.env MAINTENANCE_MODE=true npm run db:snapshot -- --output source-final-001.json
```

目标输出命名 target-final-001.json。将两个报告安全复制到同一台机器的 reports 目录后：

```bash
npm run db:compare -- --source reports/source-final-001.json --target reports/target-final-001.json
```

比较退出码：0＝快照覆盖范围一致；1＝内容或结构不一致；2＝停写、独立端点或未完成批次条件不足。每张表包含全量行内容 SHA-256、精确计数、ID 边界、列与索引信息。所有表必须存在；读取失败不能降级成空结果 PASS。

比较器保守地比较结构。MariaDB 与 MySQL 对 JSON、整数显示宽度、默认值等元数据表达不同，异构迁移可能在数据内容一致时仍报告 schema 不一致。**不得删除结构字段来凑 PASS**：导出两端 SHOW CREATE TABLE，由 DBA 确认转换语义、业务写入与 DTS 校验结果并记录例外；当前程序没有自动批准异构结构差异的功能。

快照仅覆盖这八张表，不涵盖账号、授权、存储过程、触发器、事件或外部服务。物理文件大小不参与一致性判定。

### 7.5 回退原则

在目标尚未接受业务写入前，可保持目标停写，确认原源库和应用版本后恢复源端服务。**目标已接受写入后，不能简单把连接切回旧源库**；必须先停目标写入，核对新增变化并完成反向同步或人工对账，确定数据完整性后再恢复。保留双端备份、最后 Marker、快照、比较报告和切换记录。

## 八、诊断与运行维护

| 问题 | 排查与处理 |
|---|---|
| 页面显示数据库错误 | 先执行 verify-configured.bat 或 db:ready；核对配置文件选择、连接地址、权限和八张表 |
| ECONNREFUSED | 数据库未启动、地址/端口错误、防火墙阻断 |
| ER_ACCESS_DENIED_ERROR | 用户密码、账号来源地址、TLS要求或授权不匹配 |
| 3030/33317 已占用 | 停止本项目之前的实例；不要随意杀掉不明进程，便携脚本拒绝接管非本项目数据目录 |
| DB 缺表 | 新源实验库可 db:init；目标迁移库等待 DTS，不能先造数 |
| 503 只读 | 检查 .maintenance、MAINTENANCE_MODE、DB_READ_ONLY；停写验证期属于预期行为 |
| 409 删除失败 | 该门店或设备有历史关联记录，系统保护历史数据 |
| 下载超时 | 检查官方站点和代理，重新执行；分段下载支持复用已完成块 |
| 批次一直 RUNNING | 核查进程、在途事务与审计；异常断电可能留下状态，不要直接重放整批或跳过最终检查 |
| db:compare schema 不同 | 查看完整结构差异；异构迁移需 DBA 核实，不能只比较行数 |
| verify-local 被只读阻止 | 当前目录存在 .maintenance 或环境只读；确认没有进行割接后再解除 |
| 图表为零 | 先确认有 flow_events、时间范围、业务时区；演示种子不会自动产生大量客流 |

/live 表示应用进程能响应；/health 还要求数据库及八张表可读，数据库不可用返回 503。它们不代表所有业务流程、迁移链路或外部设备可用。

生产数据库定期备份并做恢复演练；日志由 systemd journal 管理，应用报告保存在 reports。快照包含结构、摘要和脱敏端点信息，仍应按内部运维资料保管。

## 九、可复现验证命令

```powershell
npm ci
npm run lint
npm test
$env:ENV_FILE = '.env.local'
npm run test:integration
```

运行集成测试前确保本地数据库已启动。远程数据库默认拒绝写入集成测试；只有在你明确批准独立测试库后才设置 ALLOW_REMOTE_TESTS=isolated-databases。这仍要求测试账号有建库权限。不要在正式业务库直接运行造数脚本。

浏览器自动化脚本为 tests/browser.js，需额外可用的 Playwright 模块和 Chrome；默认连接 http://127.0.0.1:3030，只用于本地可写测试环境，会创建并删除自己生成的测试设备。可通过 PLAYWRIGHT_MODULE 指定模块路径、CHROME_PATH 指定 Chrome 程序。它不属于生产运行依赖。

Rocky 部署目录可执行 APP_DIR=/opt/passenger-flow-codex ENV_FILE=/opt/passenger-flow-codex/.env bash deploy/verify.sh 进行只读验收；该脚本不安装依赖、不建库。
