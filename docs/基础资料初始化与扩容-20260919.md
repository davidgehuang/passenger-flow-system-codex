# 门店与设备初始化、扩容使用说明

版本：0.3.2；日期：2026-09-19。

## 1. 为什么以前只有 5 家、10 台

`npm run db:seed` 是固定示例：5 家门店，每家 2 台设备。不是数据库上限。原有网页“新增门店”“新增设备”仍可逐条操作。

本次新增统一批量服务、网页 `/base-data`、命令行 `db:base-data` 和 Windows `base-data.bat`。没有表结构变更、没有新增生产依赖。现有 `.env` 未修改，不自动向 AWS 或 DTS 目标端写入，不打包、不自动 Git 提交。

## 2. 网页使用

1. 更新代码并重启应用。进入 Stores（门店）或 Devices（设备），点击“批量初始化／扩容”。
2. 选择操作方式：
   - **补齐**：门店数是目标总数，设备数是每家至少数量。已有 5 家、每家 2 台，补齐到 50 家、每家 4 台，正常会新增 45 家、190 台，达到 50 家、200 台。
   - **追加门店**：数量都是本次新增量。例如新增 10 家、每家 3 台，增加 10 家和 30 台。
   - **追加设备**：多选已有门店，每家增加指定设备数。Windows 可用 Ctrl/Shift 多选。
3. 点击“只读预览”，核对当前、本批新增和完成后数量；预览不写数据库。
4. 点击“确认执行预览结果”。成功后可以查看门店、设备，或去 Migration Lab 生成客流。
5. 再次追加请点“开始新批次”。新增门店之后，如需在多选框选择这些门店，刷新页面获取最新列表。

补齐包含所有现有门店和设备，关闭/停用状态也计数，保留原状态和资料。已超目标不删除、不减少；新增资料使用模拟名称、新门店 ACTIVE、新设备 ONLINE。工具限制每店参数 1–100、执行后至多 500 家／5,000 台。这是批量工具的范围，不是数据库或逐条管理的数量上限。

补齐不足时会为关闭门店也补充模拟设备。请根据实验需求选择补齐或指定门店追加。批量创建不生成历史客流；不会更改已有设备的门店关联。

## 3. 命令行

在项目目录运行，默认读取 `.env`。测试便携本地库时，PowerShell 先执行：

```powershell
$env:ENV_FILE = '.env.local'
```

先预览，再去掉 `--dry-run` 执行：

```bash
npm run db:base-data -- --mode ensure --stores 50 --devices-per-store 4 --dry-run
npm run db:base-data -- --mode ensure --stores 50 --devices-per-store 4
npm run db:base-data -- --mode append --stores 10 --devices-per-store 3
npm run db:base-data -- --mode append --store-ids 1,2 --devices-per-store 2
```

`store-ids` 是已有门店 ID，不是门店编码。指定 ID 与 `--stores` 互斥。`--dry-run` 不带值；参数必须为整数，未知参数会拒绝。CLI 执行前会自动读取一次最新预览并输出结果；它不等待第二次交互确认。只想查看时务必带 `--dry-run`。

Windows 同等入口（在 PowerShell 中）：

```powershell
.\base-data.bat --mode ensure --stores 50 --devices-per-store 4 --dry-run
.\base-data.bat --mode ensure --stores 50 --devices-per-store 4
```

无参数双击 BAT 只显示用法，不写入。已有的一键启动 BAT 无需改变。

### 重试、并发与错误

每次命令输出一个 UUID 批次号。若连接中断或不确定是否完成，保持原参数并使用原批次号：

```bash
npm run db:base-data -- --mode append --stores 10 --devices-per-store 3 --request-id 此处替换为上次输出的UUID
```

- 同批次已完成则返回 `replayed: true`，不重复新增；显示的是原批次完成时数量，不是当前总量。
- 同批次号换参数会拒绝；要进行另一批追加，使用新批次号。
- 网页执行前保存待确认批次到当前标签页的 sessionStorage。响应丢失后刷新同一标签页，再点执行可重试原批次。不要在结果未知时直接开始新批次，否则那是新的追加请求。
- 预览后资料变化会返回 409，重新预览；编码冲突或写入失败整批回滚，已有资料不覆盖。
- 只读/维护模式禁止执行；预览仍可读。数据库锁等待超时请保留批次号重试。
- 成功批次与资料在同一事务写入现有 `migration_batches`，类型 `BASE_DATA`。请保留这类批次记录，否则无法保证后续历史请求重放保护。无变化的补齐也记录一次批次，可能使“八张业务表总行数”增加 1，但门店/设备不会增加。

## 4. 与旧初始化、造数的关系

- `db:seed` 无参数保持 5 家、10 台示例行为，便携启动不意外扩容。
- `db:generate` 未传 `--stores`、`--devices-per-store` 时保留旧行为。
- 显式传入任意数量参数时，改用统一补齐：缺省目标门店数 5，缺省每店设备数 4；作用于全部已有门店及本次补建门店。空库显式初始化创建模拟名称，不再额外叠加固定五家。

```bash
npm run db:generate -- --rows 2000 --days 7 --stores 50 --devices-per-store 4
```

参数会在写入基础资料前校验。基础资料提交和客流生成属于两个阶段；如果客流生成之后失败，已经创建的基础资料会保留。重跑补齐不会重复增加资料，但造数本身仍是新增客流。

新增设备自动进入后续客流随机选择范围，无需重启。小批量不保证每台都有客流。日志改为从全部候选设备随机、不重复抽取，数量仍为每个分块最多 10 台，不再固定选择前 10 台。持续负载的单条 INSERT 原来不生成模拟设备日志，此数量规则本次保持不变。

## 5. 接口与实现说明

- `GET /api/base-data/preview`：支持 `mode`、`stores`、`devicesPerStore`、`storeIds`（逗号分隔）、`requestId`，或网页使用的 JSON `payload` 参数；返回 `params/before/added/after/previewToken`，禁止缓存。
- `POST /api/base-data/execute`：JSON 提交预览的 `params` 字段加 `previewToken`；返回 `before/added/after/requestId/replayed`。
- 沿用应用认证、跨站写入与维护模式保护；目标数限制仅在后端统一服务决定，前端校验不是安全边界。
- 同库扩容使用数据库互斥锁；事务内重新锁定资料、核对预览、分组插入，并保存请求指纹和结果。没有全局数据库配置修改，不需要 PROCESS 权限。
- 执行短时间持有门店/设备锁，会与同时编辑或造数竞争。大规模扩容建议避开高负载；若失败回滚，请保留批次号重试。

## 6. 本地验证

```powershell
npm run lint
npm test
$env:ENV_FILE = '.env.local'
npm run test:base-data
npm run test:integration
node tests/storage-integration.js
```

MariaDB 改为 `.env.mariadb-test`，数据库应预先启动。集成测试仅接受回环数据库，创建独立 `pf_base_*` 库并保留，不向现有业务库写入。账号需有创建测试库权限；故障回滚测试需要创建/删除测试触发器。浏览器测试通过 `PLAYWRIGHT_MODULE` 指定已有 Playwright 模块、`CHROME_PATH` 指定 Chrome，可选依赖不进入生产 package.json。

## 7. 更新、提交与回退

本次不需要数据库结构迁移。由你检查 Git 差异、加入新增文件后自行提交推送；在 AWS 源码目录拉取提交，再按原部署流程同步到 `/opt/passenger-flow-codex`，保留 `.env`，重启 passenger-flow 服务。如 `.env` 固定旧 APP_VERSION，可留空以显示 0.3.2。然后打开 `/base-data` 先做只读预览，再按实际需求执行。DTS 迁移中的目标端保持停写，不执行扩容。

```bash
git status --short
git diff --check
git diff
git add services/baseDataService.js routes/baseDataRoutes.js scripts/base-data.js public/js/base-data.js views/base-data.ejs base-data.bat tests/base-data-integration.js docs/基础资料初始化与扩容-20260919.md docs/基础资料扩容测试报告-20260919.md
git add -p
git diff --cached
git commit -m "Add configurable store and device initialization and expansion"
git push
```

不提交 `.env`、测试数据库、node_modules、reports。回退代码不会删除已新增的资料；保留 BASE_DATA 批次记录以支持重新升级后的重试判断。不要通过删除门店、设备或批次记录来代替代码回退。
