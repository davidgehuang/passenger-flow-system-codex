# 客流管理与数据库迁移实验系统 PRD（现状版）

> 基线：仓库 `package.json` 版本 0.3.2；编写日期：2026-09-23。本文描述代码已经提供的行为，是交接与验收基线，不代表最初提出需求时的原始文档，也不包含尚未实施的产品承诺。

## 1. 产品定位与使用者

系统用于管理**模拟门店、设备与客流数据**，并为 AWS／本地数据库到腾讯云数据库的迁移实验提供可观察的写入负载、停写、标记及一致性检查。它是单进程 Node.js Web 应用加一组运维命令，连接一个由配置指定的 MySQL/MariaDB 业务库。实际 DTS 任务的创建、状态判断及跨云链路验证仍由云平台和运维人员完成。

| 使用者 | 在系统中的工作 | 当前访问方式 |
|---|---|---|
| 实验操作者 | 查看客流、管理门店设备、执行造数、观察迁移 | 浏览器；配置了 APP_AUTH 时使用同一个 Basic Auth 账号 |
| 数据库／迁移管理员 | 初始化表、检查数据库、执行停写与双端快照、分析比较报告 | CLI、数据库与云平台控制台 |
| 运维交接人员 | 启停服务、核对配置、检查健康与部署状态 | Windows BAT 或 Rocky systemd、反向代理、CLI |

当前只有一个可选的应用级账号密码，没有按角色划分的“只看报表”“允许删除”“迁移管理员”等权限。门店及设备状态字段是业务展示与筛选属性，不构成操作权限。

## 2. 目标、范围与数据口径

### 2.1 当前可验收目标

1. 在已建好的业务数据库和账号上自动检查并按配置补齐八张表；本地试用提供便携数据库入口。
2. 查看门店、设备、客流明细和看板；根据时间、方向、门店查询客流。
3. 创建模拟基础资料和客流，通过批量增删改、持续负载和阶段标记观察迁移期间的数据变化。
4. 停写后分别为源库、目标库生成全表一致性快照，比较内容、结构与行数，辅助人工割接决策。
5. 区分应用存活、数据库就绪和容量统计的不同含义，失败时提供可排查状态。

### 2.2 指标定义

| 名称 | 当前算法／含义 | 不能解读为 |
|---|---|---|
| 客流事件 | `flow_events` 的一行，一次方向为 IN 或 OUT 的设备记录 | 一个唯一访客 |
| 人次／人数卡片 | 对事件 `people_count` 求和；“今日总客流”是 IN 与 OUT 之和 | 去重后的自然人数 |
| 今日净进店人数 | 今日 IN 人次减今日 OUT 人次 | 实时在店人数或库存式占用量 |
| 今日高峰时间 | 今日 `flow_events` 按事件小时汇总后最高的一小时 | 瞬时峰值 |
| `flow_hourly.peak_count` | 当前写入逻辑中的小时 IN＋OUT 累计人次 | 瞬时客流峰值 |
| 生成 +N MiB | 造数器写入 JSON `metadata` 的**逻辑负载目标**，受单次最多 200,000 行约束 | 精确新增 N MiB 物理磁盘 |
| 数据库容量 | 当前库全部基础表 `DATA_LENGTH + INDEX_LENGTH` 的存储引擎估算；展示 MiB／GiB 和原始字节 | RDS 实例已用磁盘或 CloudWatch FreeStorageSpace |
| 精确行数 | 当前八张业务表各 `COUNT(*)` 的采样结果 | `information_schema.TABLE_ROWS` 的近似值，或跨查询原子快照 |

容量可能按页阶梯式变化，InnoDB 引擎统计自身也可能延迟；网页每 10 秒请求不保证每次插入都使容量数字增大。详细实现见[架构手册](系统架构手册.md)。

## 3. 业务场景与操作流程

### 场景 A：首次启动与日常查看

1. 运维人员先创建数据库及应用账号，配置 `.env` 或本地独立环境文件；启动前检查八张表。源端可按 `AUTO_INIT_SCHEMA=true` 补表，DTS 目标端应保持 `false` 并等待迁移建表。
2. 演示环境运行 `db:seed` 创建固定五家门店、十台设备，或在 `/base-data` 预览并批量补齐／追加。**建表本身不会生成客流**。
3. 浏览器查看首页统计和六种图表，在 Stores、Devices、Flow Events 页面管理或查询数据。首页图表由请求时 SQL 聚合，容量卡片独立轮询。

### 场景 B：生成迁移数据

1. 至少有一个门店和有效关联设备后，可在 Migration Lab 执行 INSERT、UPDATE、DELETE、生成逻辑负载或清除估计行数；也可启动持续负载并配置目标 QPS 与操作比例。
2. 批量操作写入 `migration_batches`，每块最多 250 条事件在事务内同步维护 `flow_hourly` 和审计样本。已提交块会保留；整批失败不代表所有先前块回滚。
3. 阶段 Marker 写入独立顺序号，供源／目标端对照。设备状态日志只在批量插入时按既有比例模拟生成，不代表真实设备主动上报。

### 场景 C：迁移核验与割接辅助

1. 源端确认 DTS 任务预检、全量／增量状态和目标权限；应用的 `dts:precheck` 只覆盖它能读取的数据库属性。
2. 停止持续负载，启用维护／只读模式并确认在途写入结束；对源端及目标端分别执行 `db:snapshot`。
3. 用 `db:compare` 比较八张表的行数、主键边界、逐行摘要、列和索引结构。PASS 表示所比较的两份快照在这些范围内一致；仍需 DTS 控制台校验、网络与目标应用验收。目标开始独立写入后，回切必须另做数据对账。

## 5. 非功能约束与失败行为

- **兼容性**：声明 Node.js >=22.2.0；MySQL 8.0/8.4 与 MariaDB 10.3.39 是当前适配目标。数据库使用 InnoDB、utf8mb4，业务库名经限制；实际目标版本需重新验证。
- **数据库权限**：业务库和账号先由运维创建。自动补表需要 CREATE 权限；DTS 复制账号和应用账号应区分。八张表没有数据库外键，由应用维持关联。
- **访问**：应用仅监听回环地址。云环境要求完整 Basic Auth 配置，公网入口由受控 HTTPS 代理或负载均衡器提供。当前保护不等于细粒度授权或正式安全审计。
- **写入保护**：维护文件、`MAINTENANCE_MODE=true` 或 `DB_READ_ONLY=true` 会阻断应用写入；对数据库外部写入者没有约束。
- **失败呈现**：容量读取失败保留最后一次成功值并标明过期；首次失败显示读取失败。批量扩容在单事务内回滚；Migration Lab 大批次按块提交，需查看批次实际受影响数。
- **可用性**：应用为单实例进程设计；持续负载运行状态保存在内存中，进程重启不自动恢复。没有集群协调、任务持久化或自动故障转移实现。

## 6. 不在当前实现范围

真实摄像头接入与远程设备控制；访客身份识别或去重；多用户和角色权限；正式报表导出；自动创建、操控或验收腾讯云 DTS 任务；跨云部署编排；RDS 实例磁盘容量实时采集；高可用与灾备自动切换。若未来要产品化，应另立需求并核定数据来源、合规、权限及可用性目标。
