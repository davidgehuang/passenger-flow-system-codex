## 7. 修复后的运行原则

1. 每个环境使用自己的 .env；源端、目标端、便携本地库不要混用。
2. 存量数据库先备份并检查结构；db:init 不自动迁移旧结构。
3. 批次采用分块提交。进程中断后检查审计和实际影响行数，不盲目整批重放。
4. .maintenance 只影响本目录进程；全局停写必须涵盖所有应用、脚本、计划任务和数据库写入账号。
5. 源端最后 Marker 写入后再停写；目标端接受新写入后不能直接切回旧源。
6. 历史数据和旧生成器造成的旧汇总不因代码更新自动修正。发现存量 flow_hourly 与 flow_events 不一致时，应先备份、停止写入并以事件为准制定重建；本次没有修改现有业务库历史数据。
7. 全表快照会扫描全部数据，数据库较大时选择低峰期并确保 binlog/磁盘容量。
